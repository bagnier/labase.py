# Phase 3 — UI mockup (`features/<name>.mockup.html`)

Produce an **HTML mockup** of the feature's screens and interactions, **before any code**.

- Single static `.html` file at `features/<name>.mockup.html` (no backend, inline CSS is fine).
- Show the full page layout for each relevant state (empty, populated, error…).
- Mark interactive elements clearly (forms, buttons, links).
- HTMX attributes (`hx-post`, `hx-swap`…) may appear as hints but are not required.
- Keep it rough — it's for alignment, not production.

Iterate with the user until layout and interactions are agreed. Update the scenarios
accordingly. **No Python code yet.** Wait for user validation before Build.
